Capstone

Dossier

An AI investigation agent for VC first-meeting prep. Paste a company, URL, or pitch deck. Get a one-page brief where every claim is anchored to a verbatim quote — in 2–4 minutes.

Anthony Ugwu · 14-day solo build

Problem

VC first-meeting prep is grunt work

A seed-stage partner sees 30+ pitches a week. Every meeting starts the same way — open 15 tabs, build a mental model from press, GitHub, Crunchbase, and founder blogs. Most of the prep time vanishes before the conversation that actually matters.

What's already out there

ToolThe catch
Crunchbase / PitchBookPaid · structured data only · no inline citations
Stock LLMsFluent but hallucinate. URLs are made up half the time.
"Deep research" toolsGeneric · expensive per query · no fact-check loop

I wanted an agent that reads public sources and proves every claim with a quote a panelist can ctrl-F.

Solution

Paste · wait 2–4 min · get a cited brief and chat

Six fixed sections

Founders · Company · Market · Product · Risk Flags · Suggested Questions.

Each section is a list of claims. Each claim carries a verbatim quoted_span and a source_chunk_id — clickable in the brief, ctrl-F-able on the page.

Constraints I held to

  • Public sources only — Exa, GitHub, Firecrawl, NewsAPI, Crunchbase free.
  • No paid providers, no LinkedIn (ToS).
  • Chat answers come from the same corpus, not the model's world knowledge.
  • Nothing ships unless the eval set says it does.

Run it end-to-end

  1. Submit a company"Anthropic" — name input. Status flips queued → gathering → grounding → complete.
  2. Open the briefWalk the six sections. Click a citation. Verify the quote on the source page with ctrl-F.
  3. Eval scorecardCitation precision · grounding rate · total / grounded claims for this run.
  4. Chat over the corpus"Who founded Anthropic?" → cited answer. "What did they release in 2025?" → triggers widen-search when retrieval is weak.
  5. Pitch-deck pathUpload a PDF (MarkItDown extracts). The graph treats the deck as the corpus.
  6. Langfuse traceOne trace per investigation, span per node, tokens + latency per LLM call.

Two non-trivial things LangGraph gives me free: checkpoint resume via AsyncPostgresSaver (Lambda kills don't lose work) and the Send pattern with additive list reducers (parallel branches concatenate without races).

                ▼                              ▼
     PIN with source-absolute        persist with NULL chunk_id

Why not LLM-as-judge for citations? Substring is reproducible (same input → same score), free at grounding time, and a paraphrase doesn't earn a citation by definition. Eval and grounding share the same normalize() function object — drift is structurally impossible.

Prompt engineering

Structured outputs are the contract

   class Brief(BaseModel):                        ── extra="forbid"
       founders:            list[BriefClaim]      ─┐
       company:             list[BriefClaim]       │  six fixed sections
       market:              list[BriefClaim]       │
       product:             list[BriefClaim]       │  refusal or parsed=None
       risk_flags:          list[BriefClaim]       │  raises PipelineError
       suggested_questions: list[BriefClaim]      ─┘  (fail FAST)

   class BriefClaim(BaseModel):
       claim_text:      str
       quoted_span:     str   ── must be verbatim from a chunk
       source_chunk_id: str   ── pins the citation

   class FounderCandidates(BaseModel):            ── refusal → []
       founders: list[FounderCandidate]              capped at 5
                                                     (fail OPEN)

   class _ClassifierVerdict(BaseModel):           ── refusal → "clean"
       verdict: Literal["clean", "injection"]        every chunk, pre-synth
       reason:  str                                  (fail OPEN)

   class ChatAnswer(BaseModel):                   ── extra="forbid"
       answer_text:     str
       cited_chunk_ids: list[str]

Every LLM call goes through openai.beta.chat.completions.parse(response_format=…). The synthesizer fails fast — a malformed Brief is worse than no Brief. Everything else fails open: an outage in the cheap fan-out shouldn't kill an investigation.

How I know it's working

Every investigation is one Langfuse trace. Each graph node is a span. Every LLM call records model, tokens, latency, and structured input/output (PII-redacted with regex pre-emit). When a brief looks wrong, the trace tells me which node lied — usually the synthesizer when retrieval thinned out.

What's running right now

Vercel hosts the Next.js frontend, auto-deployed on main. AWS Amplify runs the same Next.js build in parallel — same backend, two clouds, demo-day fallback. AWS Lambda runs the FastAPI backend in a container image (Mangum bridges ASGI). One RDS Postgres + pgvector + RDS Proxy holds claims, chunks, eval data, and chat history.

A single Terraform stack provisions ECR, RDS, IAM, the Lambda, the Function URL, the Amplify app, and the SSM-backed runtime env — one terraform apply from clean.

Two safety rails worth calling out

  • The Lambda refuses to boot if DOSSIER_AUTH_DEV_BYPASS is set — that env var disables auth and must never reach prod.
  • The investigate path self-invokes asynchronously (boto3 InvocationType=Event) so POST /investigations returns 202 well under the 30s Function URL budget. The graph runs on a fresh container.
Tradeoffs

What got rejected and why

DecisionRejectedWhy
LangGraph Custom orchestration · LCEL Checkpoint resume + Send fan-out are non-trivial to DIY. State machine has explicit cycles; my code stays linear.
pgvector on RDS Pinecone · Weaviate One Postgres for everything. Single backup, single pool, scale fits.
Exa Tavily · Bing Exa returns excerpts long enough to substring-match. Tavily collapses to summaries — the quote is gone.
Substring grounding LLM-as-judge Deterministic, free, reproducible. A paraphrase doesn't earn a citation.
Sonnet + Haiku split Sonnet everywhere Sonnet for the one decision-impacting call (synthesis, chat). Haiku for the cheap fan-out (founder extraction, classifier).
OpenRouter via openai SDK Direct Anthropic SDK Multi-model fallback with one client. Embeddings still go direct to OpenAI — OpenRouter doesn't proxy /v1/embeddings.
One Lambda for the demo Two-Lambda split Production shape is the split (thin api, heavy investigate). Collapsed to one image so deploy is a single docker push — the dispatch seam is event-shape only.
Public sources only LinkedIn · paid providers ToS risk, no API surface, demo timeline. GitHub + press cover founder fact-check.
Roadmap

What I'd build with another two weeks

Quality

  • Cross-encoder re-rank on top-k before synthesis. Retrieval is pure cosine right now.
  • Vision pipeline for image-heavy decks. MarkItDown handles text; rasterized slides lose content.
  • LLM-judge eval as a second-tier metric next to deterministic precision — measures faithfulness beyond verbatim quoting.

Product

  • Streaming chat via SSE. Currently a JSON round-trip.
  • Chat history in the prompt — turns are stateless to the LLM today; follow-ups lose context.
  • Two-Lambda split for production: 30s api-lambda + 900s investigate-lambda. Dispatch seam is already there.
  • Per-source freshness: refetch sources older than N days on re-run.
Questions I expect

Sharp ones, with crisp answers

"How do you know it works?"
Ten-company eval set, four held-out and never tuned. Three metrics: citation_precision (deterministic substring), grounding_rate (synth → grounder acceptance), brief_similarity (cosine vs hand-authored gold, on a 3-company subset). Numbers ship from the live DB, not a notebook.
"Why LangGraph instead of writing it yourself?"
Two things you don't get for free: AsyncPostgresSaver checkpoints (Lambda kills resume from the last node) and the Send pattern with additive list reducers (parallel branches concatenate without races). I'd reimplement both and the result would be worse.
"What's your weakest spot?"
Founder extraction depends on Stage-1 sources mentioning founders. For stealth or pre-launch companies it's thin, and Stage-2 falls back to Crunchbase only. Honest fix is vision on pitch decks plus an explicit "founders" field on the form.
"Are you passing chat history back to the model?"
Not yet — every turn is stateless to the LLM. History persists for the UI but doesn't go back into the prompt. Adding the last 6–10 turns is small; capping is needed because briefs are token-heavy.
"What's the cost per investigation?"
~$0.15 in LLM tokens. Sonnet synthesis dominates at ~$0.10. Tools are free-tier; Lambda + RDS adds cents per day.
"How would you scale this?"
Two-Lambda split first (30s api + 900s investigate). Then SQS in front of investigate-lambda for backpressure. RDS Proxy already multiplexes; pgvector handles the corpus. The synthesizer is the rate-limit — batch by user, queue by priority.
