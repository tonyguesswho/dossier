Problem → Solution

Every pitch meeting starts with the same 15 tabs.

The gap

  • A seed partner sees 30+ pitches a week — the prep never changes, only the company does
  • ChatGPT / Perplexity: confident-sounding, but sources are often made up
  • Crunchbase / PitchBook: good data, but no way to see where it came from
  • "Deep research" tools: expensive, generic, no verification step

The real problem isn't speed — it's trust. You can't walk into a meeting and cite something you can't verify.

How Dossier solves it

  • Searches 5 real sources, builds a private research library for that company
  • Every claim comes with the exact quote it was pulled from — you can find it yourself on the source page
  • Citations are checked with a text match, not by asking another AI to vouch for them
  • 4 of 10 test companies were set aside from day one and never used to tune the system — so the accuracy numbers are real

Ground rules

  • Public sources only — Exa, GitHub, Firecrawl, NewsAPI, Crunchbase free tier
  • Chat answers only use what was found for that company — no hallucinated world knowledge

Two things LangGraph gives for free: checkpoint resume via AsyncPostgresSaver (Lambda kills don't lose work) and the Send pattern with additive reducers (parallel branches concatenate without races).

                        ▼               ▼
                   normalize()      normalize()
                  (lower · collapse ws · strip punct)
                        │               │
                        └─── in? ───────┘
                                │
                ┌──────── yes ──┴── no ────────┐
                ▼                              ▼
     PIN with char offsets              NULL chunk_id
     grounded = TRUE                    counts as hallucination

Why not LLM-as-judge? Substring is reproducible (same input → same score) and free at grounding time. A paraphrase doesn't earn a citation by definition. Eval and production share the same normalize() function object — drift is structurally impossible.

Engineering practices

Tests · Observability · Security

Testing — 176 tests

  • 157 unit — fail-open paths, security invariants, PII regex, grounding offsets, checkpoint resume
  • 19 integration — FastAPI TestClient + real Postgres + pgvector ranking
  • All green in <8s on every push

Observability — Langfuse

  • One trace per investigation, span per graph node
  • Tokens + latency per LLM call — not "it works on my machine"
  • PII-redacted at emit (regex pre-emit, not at DB write — grounding needs verbatim text)
  • Lambda: flush() → shutdown() → sleep(15) — without it ~30% of traces are lost when the container freezes

Injection defense — 3 gates

  • Gate 0 · Pydantic — denylist at API boundary; rejects "ignore previous", backticks, raw newlines
  • Gate 1 · Sandbox tags — <retrieved_content> wraps every chunk; system prompt labels it UNTRUSTED DATA
  • Gate 2 · Haiku classifier — runs on every chunk before Sonnet; fail-open degrades 3 gates to 2, not to 0

LangGraph Custom orchestration AsyncPostgresSaver checkpoint resume + Send fan-out with additive reducers — both non-trivial to DIY
pgvector on RDS Pinecone · Weaviate One Postgres for claims, chunks, eval, and chat. Single backup, single pool, no second service.

Sonnet + Haiku split Sonnet everywhere Haiku for cheap fan-out (founder extraction, classifier). Sonnet for the one decision-impacting call (synthesis, chat).

Lambda uses a container image (not zip) because pdf2image needs poppler at the OS level. One terraform apply provisions ECR, Lambda, RDS, RDS Proxy, IAM, Amplify. The Lambda refuses to boot if DOSSIER_AUTH_DEV_BYPASS is set — that env var must never reach prod.

Questions I expect

Sharp ones, with crisp answers

"How do you know it works?"
Ten-company eval set, four held-out and never tuned. Three metrics: citation_precision (deterministic substring — 100%), grounding_rate (83%), brief_similarity (cosine vs hand-authored gold, 3-company subset). Numbers come from the live DB, reproducible by anyone with the checkout.
"Why LangGraph instead of writing it yourself?"
Two things you don't get for free: AsyncPostgresSaver (Lambda kills resume from the last node — no lost work) and the Send pattern with additive list reducers (parallel branches concatenate without races). I'd reimplement both and the result would be worse.
"Can the Haiku classifier itself be prompt-injected?"
Yes — that's why it's the third gate, not the only one. Gates 0 and 1 sit upstream and don't depend on it. Haiku outage or refusal degrades 3 layers to 2, not to 0.
"What's your weakest spot?"
Founder extraction depends on Stage-1 sources mentioning founders. For stealth or pre-launch companies it's thin, and Stage 2 falls back to Crunchbase only. Fix: vision pipeline for pitch decks + an explicit "founders" field on the form.
"Are you passing chat history back to the model?"
Not yet — every turn is stateless to the LLM. History persists in the DB and renders in the UI but doesn't go back into the prompt. Adding the last 6–10 turns is one concat; capping is needed because briefs are token-heavy.
"What's the cost per investigation?"
~$0.15 in LLM tokens. Sonnet synthesis dominates at ~$0.10. Tools are free-tier. Lambda + RDS adds cents per day at this volume.
